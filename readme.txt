Connects a personal Dropbox account to the media modal and publishes galleries of Dropbox folders on the site, kept up to date as the folder changes.

== Description ==

DW Dropbox Connect puts a personal Dropbox account inside the native `wp.media` modal. Browsing, search, download, and upload all happen on the server. The browser never receives the Dropbox token.

Import stores a copy in the Media Library with `media_handle_sideload`. Gutenberg, the classic editor, Elementor, and WooCommerce receive a normal attachment, with an ID, a local file, and metadata generated by WordPress. Published content does not keep a temporary Dropbox URL.

Send works in the other direction: the Media Library selection is copied into the Dropbox folder that is open. A name that already exists at the destination gets a suffix. The plugin does not replace, move, or delete anything in Dropbox.

No credentials are bundled. The App key and App secret come from the settings screen or from `DWDC_APP_KEY` and `DWDC_APP_SECRET` in `wp-config.php`.

= Galleries =

A gallery shows the images of one Dropbox folder on the site, in the style of a social feed. Open Settings → Dropbox → Galleries, create a gallery, pick the folder, and place it with the Dropbox Gallery block or the shortcode `[dw_dropbox_gallery id="abcd1234"]`. Elementor and other builders can use the shortcode.

The gallery follows the folder. An image added, replaced, or removed in Dropbox changes on the site without touching the Media Library. Visitors never talk to Dropbox: the site downloads a resized JPEG once, keeps it in `wp-content/uploads/dw-dropbox-connect-gallery/`, and serves it from there.

* Grid or masonry layout, columns for desktop, tablet, and phone, and the gap between images.
* Square thumbnails or the original proportion.
* A first batch of images with a Load more button.
* Lightbox with keyboard, swipe, and focus handling.
* Optional file name as caption. Camera names such as IMG_4821 are never used as alt text.
* Order by upload date or file name, with an optional limit of up to 500 images.
* Optional subfolders.

How updates arrive:

1. WP-Cron checks each gallery at the interval chosen for it, from every 5 minutes to once a day.
2. Optional webhook: register `wp-json/dwdc/v1/webhook` under Webhooks in the Dropbox App Console. Dropbox then notifies the site when the account changes, and galleries refresh within seconds. The request is accepted only with a valid `X-Dropbox-Signature`.
3. A page served by a page cache asks the site whether the gallery changed and swaps the list in place, so cached pages do not show old images. The `dwdc_feed_changed` action fires when a gallery changes, for cache plugins that prefer to purge.

A gallery only exposes the folder it was set up with. The public endpoints accept a gallery ID and a file ID that is already in the gallery. They never accept a Dropbox path from the visitor. Anyone with `manage_options` creates galleries, and the images of a gallery are public by design.

= What the Dropbox tab does =

* Lists the current folder, opens folders, and walks back through the breadcrumb.
* Pages with the Dropbox cursor. Refresh asks for the folder again. Load more only fetches the next page.
* Searches from two characters and pages through the search results.
* Shows thumbnails for the formats Dropbox can render: jpg, jpeg, png, gif, webp, tif, tiff, and bmp.
* Imports the chosen file. With "Include in selection" checked, the attachment is added to the modal selection without leaving the Dropbox tab.
* When the sanitized name already exists in the library and the user can edit that attachment, the card offers "Already in library" and reuses that attachment without downloading again. The match is by name, not by file contents.
* In a multiple selection, several files can be marked and imported together.
* On Media → Library, the Dropbox button opens the same modal. Imported files show up in the grid when the modal closes.
* Sends the attachments marked in the library to the open Dropbox folder. In the library grid, mark the items before opening Dropbox.

= External service =

The plugin talks only to the Dropbox API, and only after an administrator connects the account:

* `https://www.dropbox.com` for the OAuth authorization.
* `https://api.dropbox.com` for metadata, search, and the token exchange.
* `https://content.dropboxapi.com` for download, thumbnails, and upload.

Gallery visitors are never sent to these addresses. The server requests the Dropbox API, and the visitor's browser only loads files from the site.

Nothing is sent on activation. There is no telemetry, advertising, or script loaded from outside the site. CSS and JavaScript ship inside the plugin.

= Dropbox permissions =

* `account_info.read` shows the account name.
* `files.metadata.read` lists and searches.
* `files.content.read` downloads files and thumbnails.
* `files.content.write` creates the copy in the open folder.

An existing token does not gain a new permission by itself. After enabling `files.content.write` on the app, disconnect and connect again.

= Who can use the connected account =

The connection belongs to the site, not to each user. Anyone with the `upload_files` capability can browse, import, and send. Anyone with `manage_options` saves the credentials, connects, and disconnects. Sending also requires permission to edit that attachment. Restrict `upload_files` if the connected account holds private files.

= What is stored in WordPress =

* App secret, access token, and refresh token, encrypted with AES-256-CBC and authenticated with HMAC-SHA256. The key is derived from the `auth` and `secure_auth` salts.
* App key and the Dropbox display name.
* Transients for listings, search, request limits, and the one-time OAuth state.
* JPEG thumbnails in `wp-content/uploads/dw-dropbox-connect-cache/`, named with an HMAC. On Apache, an `.htaccess` file denies direct access.
* Imported attachments, like any other Media Library file.
* Gallery settings (option `dwdc_feeds`) and, per gallery, the list of images last read from Dropbox (options `dwdc_feed_*`).
* Gallery images as JPEG in `wp-content/uploads/dw-dropbox-connect-gallery/`, one folder per gallery, named with an HMAC. These files are public, because the gallery is public.

Changing the salts makes the secrets unreadable and requires a new connection. Tokens stored by an older build, without the HMAC, can still be read and are rewritten in the new format the next time they are saved.

= API security =

The `dwdc/v1` endpoints require an authenticated user with `upload_files` and the `wp_rest` nonce. Each route declares the argument types. Path, cursor, and search go through their own validation: no `..`, no loose trailing slash, and no control characters. Import respects the maximum upload size and the types allowed by WordPress, including `upload_mimes`. Send only reads a file that lives inside `uploads` and that the user can edit. A thumbnail is served only when the file is inside this plugin's cache and is a JPEG.

The OAuth return uses a one-time `state` bound to the user who started the connection. The redirect to Dropbox continues only when the address is `https://www.dropbox.com` or `https://dropbox.com`.

== Installation ==

1. Copy the `dw-dropbox-connect` folder to `wp-content/plugins/`.
2. Activate DW Dropbox Connect. The PHP OpenSSL extension is required.
3. Open Settings → Dropbox.

= Dropbox App Console =

1. Create an app at https://www.dropbox.com/developers/apps.
2. Choose Scoped access and Full Dropbox. Do not use an App folder.
3. Under Permissions, enable `account_info.read`, `files.metadata.read`, `files.content.read`, and `files.content.write`. Submit the changes. If the account was already connected, connect again so the token receives write access.
4. Under Settings → OAuth 2, register the Redirect URI exactly as the plugin screen shows it. It points to `wp-admin/admin-post.php?action=dwdc_oauth_callback`.
5. Copy the App key and App secret. Paste them into the settings screen, or define both in `wp-config.php`:

`
define( 'DWDC_APP_KEY', 'paste-the-app-key' );
define( 'DWDC_APP_SECRET', 'paste-the-app-secret' );
`

The constants take priority and must be defined together. `WPDM_APP_KEY` and `WPDM_APP_SECRET` are still read when the new constants are not defined.

6. Save and click Connect Dropbox. Authorize the personal account.
7. Open the media modal in the editor, Media → Add New, or the Dropbox button on Media → Library.

While the app is in development, Dropbox only authorizes the app owner and the testers added in the console.

== Frequently Asked Questions ==

= Does an imported file stay linked to Dropbox? =

No. Import creates a local attachment. Deleting the file in Dropbox does not delete the attachment, and deleting the attachment does not delete the Dropbox file.

= Can I send files from the library to Dropbox? =

Yes. Mark the attachments in the library, open the destination folder on the Dropbox tab, and use Send selection. The plugin creates a copy. It does not replace an existing file.

= Why does sending say the permission is missing? =

The app needs `files.content.write`, and the token has to be issued after that permission was enabled. Disconnect and connect again.

= Who can see the connected account? =

Any user with `upload_files`. The connected account is shared by the site.

= How do updates arrive? =

WordPress asks GitHub for the latest release. A newer version appears on the Plugins screen when that release has a higher number and the `dw-dropbox-connect.zip` file attached. A commit on the repository does not publish an update. The site checks on its usual schedule, about every few hours, or when you open Dashboard → Updates.

= What does uninstall remove? =

The plugin options, the gallery settings and snapshots, its transients, its scheduled tasks, and both cache directories. Attachments already imported stay in the library.

= Can a gallery show a private folder? =

The images of a gallery are public. Choose only folders meant for the site. The plugin never exposes anything outside the folder chosen for the gallery.

= A new photo did not appear on the site. =

Open Settings → Dropbox → Galleries and use Refresh now to confirm the connection works. Without the webhook, the site waits for the interval of the gallery, and WP-Cron only runs when the site receives visits (or when a system cron calls `wp-cron.php`). Only jpg, png, gif, webp, tiff, and bmp files are listed. Other formats, such as HEIC, are skipped.

= Is the thumbnail cache public on Nginx? =

The `.htaccess` file only applies on Apache. If the uploads directory can be read by URL, block `dw-dropbox-connect-cache` on the server.

== Privacy ==

The plugin does not collect data for its author. Gallery visitors send nothing to Dropbox and the plugin sets no cookie for them. Requests to Dropbox carry the connected account token and the path, name, or contents of the file the user chose to list, search, import, or send. The Dropbox display name is stored on the site for the settings screen. See also the Dropbox privacy policy.
